## 2. Test Cases: Core Metric Calculations (The 4 Stat Cards)

* **UI Route:** `/dashboard/events/[id]` (Analytics Tab/Section)
* **API Endpoint:** `GET /api/v1/events/{id}/analytics`

### A. Ground-Truth SQL Cross-Check
Open a `psql` session to compare the dashboard numbers directly against the database:
```bash
docker compose exec -T db psql -U biletflow -d biletflow -c "
SELECT 
  (SELECT count(*) FROM tickets t JOIN order_items oi ON t.order_item_id = oi.id JOIN ticket_types tt ON oi.ticket_type_id = tt.id WHERE tt.event_id = e.id AND t.status IN ('valid', 'checked_in')) AS live_sold,
  (SELECT count(*) FROM tickets t JOIN order_items oi ON t.order_item_id = oi.id JOIN ticket_types tt ON oi.ticket_type_id = tt.id WHERE tt.event_id = e.id AND t.status = 'checked_in') AS live_checked_in,
  (SELECT coalesce(sum(total_kzt), 0) FROM orders WHERE event_id = e.id AND status IN ('paid', 'completed', 'refunded', 'partially_refunded')) AS gross_sales,
  (SELECT coalesce(sum(refunded_kzt), 0) FROM orders WHERE event_id = e.id) AS total_refunds
FROM events e WHERE e.slug = 'almaty-winter-jazz-night';"
```

### B. Metric Verification Cases
| Test ID | Metric Displayed | Calculation Source Rule | Verification Criteria |
| :--- | :--- | :--- | :--- |
| **ANA-01** | **Tickets Sold & Capacity** | Live valid tickets: `count(tickets in 'valid' or 'checked_in')` vs `sum(ticket_types.quantity_total)`. | Display reads e.g.: `42 Sold · of 250 capacity · 16.8% sold`. Percentage is rounded to 1 decimal place. |
| **ANA-02** | **Tickets Remaining** | Total capacity minus live sold tickets. | Matches `sum(quantity_total) - live_sold`. |
| **ANA-03** | **Gross Revenue (KZT)** | `sum(total_kzt)` across orders with status `paid`, `completed`, `refunded`. | Decimal formatted string with 2 decimal places (e.g., `"210000.00"` rendered as `210 000.00 ₸`). Cast in SQL as `numeric(14,2)::text`. |
| **ANA-04** | **Refunds & Net Revenue** | `gross_revenue_kzt - refunds_kzt`. | Net figure accurately deducts refunded orders; refunds match `refunded_kzt` sum. |
| **ANA-05** | **Check-in Attendance** | `count(checked_in)` vs `absent` (`sold - checked_in`). | Display reads e.g.: `12 Checked In · 30 absent · 28.6% attended`. |

## 5. Test Cases: Real-Time Recalculation & Mutation Resilience

Verify that actions taken in other parts of the platform instantly update analytics without drift.

| Test ID | Trigger Action | Expected Analytics Impact | Verification |
| :--- | :--- | :--- | :--- |
| **MUT-01** | Complete a new checkout (Phase 3). | `live_sold` increments by purchased ticket count; `gross_revenue_kzt` increments by order total; `remaining` decrements. | Refresh analytics tab: numbers update immediately. |
| **MUT-02** | Check in an attendee at the gate (Phase 5). | `checked_in` increments by 1; `absent` decrements by 1; `check_in_percentage` recalculates upwards. | Check-in stats reflect entry immediately. |
| **MUT-03** | Reverse a check-in (Phase 5). | `checked_in` decrements by 1; `absent` increments by 1; percentage adjusts downwards. | Counter returns to previous value. |
| **MUT-04** | Execute a full refund (Phase 6). | `gross_revenue_kzt` remains historical; `refunds_kzt` increases; `live_sold` decrements; `remaining` increments (seat returned to stock). | Refund reflected in net revenue and capacity. |

Per SRS 4.16, audit logs are append-only. Test that database triggers block any attempt to modify or erase history.

| Test ID | Scenario | SQL Test Command | Expected Result |
| :--- | :--- | :--- | :--- |
| **AUD-IMM-01** | **Attempt to UPDATE an audit log entry.** | `docker compose exec -T db psql -U biletflow -d biletflow -c "UPDATE audit_logs SET action = 'tampered' WHERE id = 1;"` | **FAILED: Trigger exception**<br>`ERROR: audit_logs rows are immutable and cannot be updated` |
| **AUD-IMM-02** | **Attempt to DELETE an audit log entry.** | `docker compose exec -T db psql -U biletflow -d biletflow -c "DELETE FROM audit_logs WHERE id = 1;"` | **FAILED: Trigger exception**<br>`ERROR: audit_logs rows are immutable and cannot be deleted` |

## Phase 7 Sign-Off Checklist
You can consider Analytics & Audit Trail **PASSED** if:
- [ ] Stat cards (Sold, Remaining, Gross Revenue, Checked In) compute dynamically from operational records and match raw SQL queries.
- [ ] Financial metrics never round off tiyn (always exact two-decimal `numeric(14,2)` precision).
- [ ] Campaign reporting accurately attributes tickets sold, discounts given, and net revenue to each promo code.
- [ ] Sales-over-time visualization renders correctly without third-party chart bundle errors.
- [ ] Date filtering treats the `to` parameter as the end of that day (`23:59:59`).
- [ ] Refunding an order decrements the sold count and restocks remaining inventory while retaining gross sales history.
- [ ] Check-in and reversal events update attendance percentages in real time.
- [ ] The activity timeline records lifecycle, order, check-in, and campaign events chronologically.
- [ ] The database trigger strictly prevents `UPDATE` or `DELETE` operations on `audit_logs`.
- [ ] Organizers cannot access analytics or audit logs for events owned by other accounts.
