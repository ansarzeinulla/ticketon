# Неделя 6 — Возвраты, поддержка, админ (19–25 октября): готовые файлы и скрипты коммита

`code/<задача>/` — файлы задачи в том виде, в каком они должны быть **на этой
неделе**. `code/<задача>.delete` — что задача удаляет. `manifest.txt` — список по
файлам (собран `tools/gitpack.py` из рабочего репозитория, где каждая задача —
отдельный коммит). `tickets.plan` — кто, в каком порядке и поверх чего.

Итог недели:
- организатор возвращает деньги за платный заказ одной транзакцией (заказ,
  платёж, билеты, остатки) и отменяет бесплатную регистрацию; покупателю
  уходит письмо, возвращённый билет не проходит на входе, а запись о входе,
  если он уже был, сохраняется;
- отказ симулированной оплаты (`@decline.simulator.biletflow.kz`) —
  `402 payment_failed`, без билетов, с письмом;
- владельцы билетов получают письмо, когда событие переносят или отменяют;
  организатор — о статусе выплат;
- поддержка: зритель задаёт вопрос со страницы заказа, организатор отвечает из
  входящих на странице события, назначает случай, ставит статус, пишет
  внутренние заметки;
- админ-портал `/admin` для `platform_admin`: поиск по пользователям,
  событиям, заказам и платежам, приостановка события, платных продаж или
  аккаунта, очередь жалоб, настройки платформы (комиссия активации), CSV-отчёт;
- безопасность веба: токен больше не живёт в JavaScript — вход через
  `/api/auth/*`, токен в httpOnly-cookie, все запросы к API идут через
  `/api/proxy`; `middleware.ts` переименован в `proxy.ts` (Next 16);
- `6.md` — спецификация возвратов; seed: платформенный админ
  `support@biletflow.kz` и случай поддержки.

## Проверено

Все тринадцать скриптов прогнаны в песочнице поверх слитой недели 5 — на GitHub
ничего не уходило (`tools/simweek.sh`):

- каждая ветка задачи собирается сама: API — `gofmt`, `go vet`, `go test` на
  PostgreSQL 17; веб — `lint`, `typecheck`, `vitest`; мобильное — `tsc`;
  `db/` — SQL-тесты с seed;
- после слияния всех тринадцати: то же плюс `next build`, SQL-тесты 01–06,
  и дерево совпадает с эталоном файл в файл;
- `make api-smoke` прогнан вживую против API недели 6: все проверки зелёные;
- у каждой ветки один коммит поверх своей базы, автор — владелец задачи, без
  соавторов, с настоящим временем.
