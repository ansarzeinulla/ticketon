# Phase 2: Organizer Event & Ticket Management Testing Specification

This specification covers **only** the Organizer's ability to create, update, publish, unpublish, cancel and delete events, upload a banner, and manage ticket types (SRS 4.2, 4.3).

---

## 1. Setup & Environment for the Tester

Treat this as an independent testing phase. You need an authenticated organizer session and access to the database and API logs.

### Terminal 1: Database
```bash
make up
make seed
```

```bash

```

## 2. Test Cases: Event Creation & Image Uploads

* **UI Routes:** `/events/new`, `/dashboard/events/[id]`
* **API Endpoints:**
  * `POST /api/v1/events`
  * `POST /api/v1/uploads/images`

### A. Normal Cases (Happy Path)
| Test ID | Input / Scenario | Expected Behavior | Expected Response / Status |
| :--- | :--- | :--- | :--- |
| **EVT-01** | Create an event filling the required fields: Title, Start and End Date/Time, Timezone (`Asia/Almaty`); add Venue Name, Venue Address, Capacity. | Event is created in **`draft`** status; a unique slug is generated from the title; the dashboard lists it. | **HTTP 201 Created**<br>`status: "draft"` |
| **EVT-02** | Upload a valid banner image (`.png` or `.jpeg` under 5 MB, at least 200×200). | The file is inspected by content (not extension), given a random name in `UPLOAD_DIR`, and a URL (`http://localhost:8080/uploads/{filename}`) is returned and shown as a preview in the form. | **HTTP 201 Created**<br>Returns `{ "url": "..." }` |
| **EVT-03** | Cyrillic title (e.g., `"Концерт в Алматы"`). | Title is accepted; the slug is transliterated to ASCII (`kontsert-v-almaty`). | **HTTP 201 Created** |

### B. Edge Cases
| Test ID | Input / Scenario | Expected Behavior | Expected Response / Status |
| :--- | :--- | :--- | :--- |
| **EVT-04** | Title collision: create two events titled `"Tech Meetup"`. | The first gets `tech-meetup`, the second `tech-meetup-2`. A slug the *client* chose is never renamed - that is a 409. | **HTTP 201 Created** for both. |
| **EVT-05** | Timezone: set start time to `19:00` with timezone `Asia/Almaty` while the browser is in another zone. | The form converts with the event's own zone; the dashboard shows exactly `19:00`, not the browser's local time. | RFC 3339 string with `+05:00`. |
| **EVT-06** | `ends_at` exactly 1 minute after `starts_at`. | Accepted. | **HTTP 201 Created** |

### C. Error Cases & What Errors Must Appear
| Test ID | Input / Scenario | Expected Error Code / Message | HTTP Status |
| :--- | :--- | :--- | :--- |
| **EVT-ERR-01** | `ends_at <= starts_at`. | **JSON:** `{"error": {"code": "validation_failed", "fields": {"ends_at": "End time must be after the start time."}}}`<br>**UI:** the End field is highlighted. | **422 Unprocessable Entity** |
| **EVT-ERR-02** | Empty title. | `{"error": {"code": "validation_failed", "fields": {"title": "Title is required."}}}` | **422 Unprocessable Entity** |
| **EVT-ERR-03** | Image over 5 MB. | `{"error": {"code": "file_too_large", "message": "That image is too large. The limit is 5 MB."}}` | **413 Payload Too Large** |
| **EVT-ERR-04** | A text file renamed to `banner.png`. | `http.DetectContentType` reads the first 512 bytes: `{"error": {"code": "unsupported_media_type"}}` | **415 Unsupported Media Type** |
| **EVT-ERR-05** | A 50×50 image. | `{"error": {"code": "invalid_image_dimensions", "message": "That image is too small. It must be at least 200×200 pixels."}}` | **422 Unprocessable Entity** |

## 3. Test Cases: Event Lifecycle & Modifications

* **UI Routes:** `/dashboard`, `/dashboard/events/[id]/edit`
* **API Endpoints:**
  * `PATCH /api/v1/events/{id}`
  * `POST /api/v1/events/{id}/publish`
  * `POST /api/v1/events/{id}/unpublish`
  * `POST /api/v1/events/{id}/cancel`
  * `DELETE /api/v1/events/{id}`

### State Machine Rules
```
         ┌───────────────┐
         │     DRAFT     │
         └───────┬───────┘
                 │ publish
                 ▼
         ┌───────────────┐  unpublish   ┌───────────────┐
         │   PUBLISHED   ├─────────────►│  UNPUBLISHED  │
         │               │◄─────────────┤               │
         └───────┬───────┘   publish    └───────────────┘
                 │ cancel
                 ▼
         ┌───────────────┐
         │   CANCELLED   │ (terminal state)
         └───────────────┘
```

### A. Normal Cases (Happy Path)
| Test ID | Input / Scenario | Expected Behavior | Expected Response / Status |
| :--- | :--- | :--- | :--- |
| **LIFE-01** | Publish a draft. | Status becomes `published`; the event appears in `GET /api/v1/events` and at `/events/[slug]`. A toast says *"Event published."* | **HTTP 200 OK** |
| **LIFE-02** | Unpublish a published event. | Status becomes `unpublished`; the event leaves the public catalogue and can be published again. | **HTTP 200 OK** |
| **LIFE-03** | Cancel a published event (the dashboard asks for confirmation first). | Status becomes `cancelled`; checkout is refused from now on. | **HTTP 200 OK** |
| **LIFE-04** | Delete a draft with no orders. | The row is gone from `events`. | **HTTP 204 No Content** |
| **LIFE-05** | PATCH with only `description` changed. | Only `description` changes; every omitted field is untouched. | **HTTP 200 OK** |
| **LIFE-06** | PATCH with `"description": null`. | The optional column is cleared; required fields are unaffected. | **HTTP 200 OK** |

### B. Edge Cases & Guardrails
| Test ID | Input / Scenario | Expected Behavior | Expected Response / Status |
| :--- | :--- | :--- | :--- |
| **LIFE-07** | Organizer isolation: signed in as `timur@biletflow.kz`, PATCH one of `dana@biletflow.kz`'s events. | Refused; an organizer can never change another organizer's event. A draft of someone else is not even visible. | **HTTP 403 Forbidden** (`GET` of a foreign draft: **404**) |

### C. Error Cases & What Errors Must Appear
| Test ID | Input / Scenario | Expected Error Code / Message | HTTP Status |
| :--- | :--- | :--- | :--- |
| **LIFE-ERR-01** | DELETE a published event. | `{"error": {"code": "conflict", "message": "Only a draft event can be deleted. Cancel this event instead."}}` | **409 Conflict** |
| **LIFE-ERR-02** | Publish a cancelled event. | `{"error": {"code": "conflict", "message": "A cancelled event cannot be published."}}` | **409 Conflict** |
| **LIFE-ERR-03** | Move a draft's dates into the past in the DB, then publish. | `{"error": {"code": "validation_failed", "fields": {"ends_at": "This event has already ended and cannot be published."}}}` | **422 Unprocessable Entity** |

## 4. Test Cases: Ticket Type Management

* **UI Component:** Ticket types panel on `/dashboard/events/[id]`
* **API Endpoints:**
  * `GET /api/v1/events/{id}/ticket-types`
  * `POST /api/v1/events/{id}/ticket-types`
  * `PATCH /api/v1/ticket-types/{id}`
  * `DELETE /api/v1/ticket-types/{id}`

### A. Normal Cases (Happy Path)
| Test ID | Input / Scenario | Expected Behavior | Expected Response / Status |
| :--- | :--- | :--- | :--- |
| **TKT-01** | Free ticket type: `price_kzt: "0"`, `quantity_total: 100`, `name: "Free Registration"`. | Created; `is_free: true`, price shown as `"0.00"`. | **HTTP 201 Created** |
| **TKT-02** | Paid ticket type: `price_kzt: "5000.00"`, `quantity_total: 50`. | Stored as `numeric(14,2)`, returned as the string `"5000.00"`. | **HTTP 201 Created** |
| **TKT-03** | Hide a ticket type (`is_hidden: true`). | Still listed for the organizer, absent from `GET /api/v1/public/events/{slug}`. | **HTTP 200 OK** |
| **TKT-04** | Delete a ticket type with no sales. | The row is gone. | **HTTP 204 No Content** |

### B. Edge Cases & Precision Checks
| Test ID | Input / Scenario | Expected Behavior | Expected Response / Status |
| :--- | :--- | :--- | :--- |
| **TKT-05** | Prices such as `"1500.50"` or `"99999.99"`. | Handled as strings end to end; no float rounding. | **HTTP 201 Created** |
| **TKT-06** | Raise `quantity_total` from 50 to 80 with 10 sold. | Allowed; remaining becomes 70. | **HTTP 200 OK** |
| **TKT-07** | `max_per_order: 2`. | Stored, and enforced at checkout (see `3.md`). | **HTTP 200 OK** |

### C. Error Cases & What Errors Must Appear
| Test ID | Input / Scenario | Expected Error Code / Message | HTTP Status |
| :--- | :--- | :--- | :--- |
| **TKT-ERR-01** | `price_kzt: "-500"` or `quantity_total: -10`. | `validation_failed` with a field message for `price_kzt` or `quantity_total`. | **422 Unprocessable Entity** |
| **TKT-ERR-02** | With 15 sold, PATCH `quantity_total` to 10. | `{"error": {"code": "validation_failed", "fields": {"quantity_total": "Total quantity cannot be lower than the number already sold or reserved."}}}` | **422 Unprocessable Entity** |
| **TKT-ERR-03** | DELETE a ticket type that has sales. | `{"error": {"code": "conflict", "message": "This ticket type has sales and cannot be deleted. Hide it instead."}}` | **409 Conflict** |
| **TKT-ERR-04** | `sales_end_at` before `sales_start_at`. | `{"error": {"code": "validation_failed", "fields": {"sales_end_at": "Sales must end after they start."}}}` | **422 Unprocessable Entity** |
| **TKT-ERR-05** | Two ticket types with the same name on one event. | `{"error": {"code": "validation_failed", "fields": {"name": "This event already has a ticket type with that name."}}}` | **422 Unprocessable Entity** |

The window is enforced at checkout, not merely displayed.

| Test ID | Scenario | Expected Error Code / Message | HTTP Status |
| :--- | :--- | :--- | :--- |
| **RWIN-01** | `registration_opens_at` in the future; attempt checkout. | `{"error": {"code": "sales_closed", "message": "Registration for this event has not opened yet."}}` | **409 Conflict** |
| **RWIN-02** | `registration_closes_at` in the past; attempt checkout. | `{"error": {"code": "sales_closed", "message": "Registration for this event has closed."}}` | **409 Conflict** |

## Phase 2 Sign-Off Checklist
You can consider Organizer Event & Ticket Management **PASSED** if:
- [ ] Events start as drafts and get de-duplicated, transliterated slugs.
- [ ] Images over 5 MB, non-images and tiny images are rejected.
- [ ] Dates and times honour the event's configured IANA timezone (`Asia/Almaty`).
- [ ] An event that has already ended cannot be published.
- [ ] Deleting anything but a draft without orders returns HTTP 409.
- [ ] Ticket prices are exact decimal strings (`numeric(14,2)`), never floats.
- [ ] Ticket types with sales cannot be deleted, only hidden.
- [ ] Organizers cannot view or edit events owned by another account.
- [ ] Public, unlisted and private visibility behave differently in the catalogue and on the public page.
- [ ] Registration opening and closing times are enforced at checkout.
