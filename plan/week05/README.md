# Неделя 5 — Контроль входа (12–18 октября): готовые файлы и скрипты коммита

`code/<задача>/` — файлы задачи в том виде, в каком они должны быть **на этой
неделе**. `code/<задача>.delete` — что задача удаляет. `manifest.txt` — список по
файлам (собран `tools/gitpack.py` из рабочего репозитория, где каждая задача —
отдельный коммит). `tickets.plan` — кто, в каком порядке и поверх чего.

Итог недели:
- выбранные места резервируются на 15 минут и оплачиваются по таймеру; брошенный
  резерв сам возвращается в продажу (фоновая очистка раз в минуту);
- к каждому платному заказу добавляется сервисный сбор 3,5% (настраивается в
  `.env`: `PROCESSING_FEE_PERCENT`, `PROCESSING_FEE_FIXED_KZT`); бесплатная
  регистрация остаётся бесплатной;
- организатор назначает персонал на вход (панель **Gate staff** на странице
  события);
- мобильное приложение: список событий, где можно сканировать, камера, зелёный и
  красный экран, ввод кода вручную, отмена ошибочного входа, поиск гостя по имени;
- один билет — один вход: повторный скан, билет другого события, промокод
  `CMP_…` и неизвестный код отбиваются с понятной причиной;
- `make api-smoke` проверяет и вход (шаги 20–24b); в CI — отдельная джоба
  проверки типов мобильного;
- `5.md` — спецификация проверки входа; в `3.md` и `4.md` суммы пересчитаны с
  учётом сбора; seed: аккаунт сканера `scanner@biletflow.kz`, назначенный на оба
  события, и один уже использованный билет.

## Проверено

Все восемь скриптов прогнаны в песочнице поверх слитой недели 4 — на GitHub
ничего не уходило (`tools/simweek.sh`):

- каждая ветка задачи собирается сама: API — `gofmt`, `go vet`, `go test` на
  PostgreSQL 17; веб — `lint`, `typecheck`, `vitest`; мобильное — `tsc`;
  `db/` — SQL-тесты с seed;
- после слияния всех восьми: то же плюс `next build`, SQL-тесты 01–05 и 07,
  и дерево совпадает с эталоном файл в файл;
- `make api-smoke` прогнан вживую против API недели 5: все проверки зелёные,
  включая сумму `10350.00` и вход (скан, отказ повторного скана, счётчик,
  отмена входа);
- сценарии `5.md` проверены по HTTP под `scanner@biletflow.kz` на seed-данных:
  зелёный, «уже использован», «другое событие», промокод (токеном и ссылкой),
  неизвестный код, поиск по имени и вход без QR;
- у каждой ветки один коммит поверх своей базы, автор — владелец задачи, без
  соавторов, с настоящим временем.

## Кто что запускает

Каждый запускает **только свои** скрипты за этим компьютером; скрипт спросит
«Вы — …?» и подпишет коммит его именем. Перед запуском — задачу в Jira в
**In Progress**.

В этой неделе **две цепочки**. Первая — API и мобильное: резервы и сбор (S2),
настройка сбора (S1), затем вход (S5) — все они правят `server.go`. Вторая —
веб (S4, затем S3): оба правят `web/src/lib/api.ts` и `types.ts`. Цепочки не
пересекаются по файлам, поэтому вторую можно запускать в любой момент. Скрипт
сам откажется, если его база ещё не запушена, и скажет, кого ждать.

## Конец недели — PR

Каждый открывает свои PR (скрипт печатает ссылку), **base: `week-05`**.
Капитан вливает **строго в порядке таблицы**, способом **Create a merge commit**.
Пока предыдущие PR цепочки не влиты, PR показывает и их коммиты; после их
слияния остаётся только свой.

После последнего слияния:

```bash
make reset && make seed && make test   # SQL: 01–05, 07
make api-check                         # gofmt, vet, go test
make api-run                           # в отдельном терминале, затем:
make api-smoke                         # проверка по HTTP, вход — шаги 20–24b
make web-check                         # lint, typecheck, next build
make scan-install && make scan-check   # в мобильном появилась expo-camera
make scan-dev                          # Expo Go, вход как scanner@biletflow.kz
```

Задачи в Jira → **Done**, `week-05` → `main`.
