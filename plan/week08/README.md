# Неделя 8 — Релизная форма (2–8 ноября): готовые файлы и скрипты коммита

`code/<задача>/` — файлы задачи в том виде, в каком они должны быть **на этой
неделе**. `code/<задача>.delete` — что задача удаляет. `manifest.txt` — список по
файлам (собран `tools/gitpack.py` из рабочего репозитория, где каждая задача —
отдельный коммит). `tickets.plan` — кто, в каком порядке и поверх чего.

После этой недели **продуктовый код совпадает с нынешним**: дальше (W9–W10)
приходят только тесты, e2e, Postman, CI/Docker и документация.

Итог недели:
- пароль ограничивается символами, а не байтами bcrypt: перед bcrypt идёт
  SHA-256, так что казахский пароль не обрезается, а старые хеши подходят;
  настройки API: `BILETFLOW_ENV`, `API_PORT`, таймауты, пул соединений;
- seed переписан: зал на 126 мест, джаз-вечер с местами, заказ со скидкой,
  возврат, вход, случай поддержки, лента событий; повторный `make seed`
  безопасен и после покупок;
- зритель видит свои заказы: `GET /orders` и страница «Мои билеты»;
- к сообщению в поддержке можно приложить PDF (чек, распечатанный билет);
- аналитика показывает зарезервированные билеты (панель теперь
  `event-analytics.tsx`);
- сканер работает без сети: скачивает список (хеши токенов, не сами токены),
  пропускает офлайн и синхронизирует очередь; экран сканера стал маршрутом
  `scan/[eventId]`;
- отмена невошедшего билета — свой код `ticket_not_checked_in`;
- спецификации: новые `8.md`, `9.md`, `10.md`, обновлённые `1.md`–`7.md` под
  новый seed; `docs/api-notes.md` и `docs/decisions.md` удалены.

## Проверено

Все одиннадцать скриптов прогнаны в песочнице поверх слитой недели 7 — на
GitHub ничего не уходило (`tools/simweek.sh`):

- каждая ветка задачи собирается сама: API — `gofmt`, `go vet`, `go test` на
  PostgreSQL 17; веб — `lint`, `typecheck`, `vitest`; мобильное — `tsc`;
  `db/` — SQL-тесты с seed;
- после слияния всех одиннадцати: то же плюс `next build`, SQL-тесты 01–06,
  и дерево совпадает с эталоном файл в файл;
- `make api-smoke` прогнан вживую против API недели 8: все проверки зелёные;
- у каждой ветки один коммит поверх своей базы, автор — владелец задачи, без
  соавторов, с настоящим временем.
