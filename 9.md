## 4. Test Cases: Event Suspension & Reinstatement

Platform admins can intervene to shut down suspicious or fraudulent events (SRS 4.5, 4.12, Phase 8).

* **API Endpoints:**
  * `POST /api/v1/admin/events/{id}/suspend`
  * `POST /api/v1/admin/events/{id}/unsuspend`

### A. Suspending an Event
| Test ID | Step / Action | System Area Inspected | Expected State / Output |
| :--- | :--- | :--- | :--- |
| **SUSP-01** | Admin clicks "Suspend Event" on an active event. | `events.status` in database. | Status flips from `published` to **`suspended`**. |
| **SUSP-02** | Attendee visits public event page `/events/[slug]`. | Public Event View. | Page resolves (links remain active), but displays a **red warning banner**: *"Ticket sales for this event have been suspended."* The ticket selector is **not rendered at all**. |
| **SUSP-03** | Attendee attempts API checkout on suspended event. | `POST /checkout` direct request. | **HTTP 403 Forbidden**<br>`{"error": {"code": "event_suspended", "message": "This event has been suspended by the platform."}}`<br>No inventory is modified. |
| **SUSP-04** | Organizer views their own dashboard for that event. | Organizer View. | Displays suspension notice. Organizer cannot publish or change sales status while suspended. |
| **SUSP-05** | **Existing Ticket Holder Gate Check (SRS 4.12 Invariant):** Holder of a pre-purchased ticket attempts check-in at the venue. | Mobile Door Scanner. | **Ticket remains valid!** Admitted with green screen. *(Stranding attendees who already paid is not the remedy for organizer misconduct).* |

### B. Unsuspending an Event
| Test ID | Step / Action | System Area Inspected | Expected State / Output |
| :--- | :--- | :--- | :--- |
| **SUSP-06** | Admin clicks "Unsuspend Event". | `events.status` in database. | Status returns to **`unpublished`** (or `draft`), not `published`. *(The organizer must consciously review and republish their event after suspension).* |

## 5. Test Cases: Targeted Paid-Sales Suspension

Unlike full event suspension, this narrower intervention stops monetary transactions while allowing free registrations to continue (SRS 4.5, Phase 10).

* **API Endpoints:**
  * `POST /api/v1/admin/events/{id}/paid-sales/suspend`
  * `POST /api/v1/admin/events/{id}/paid-sales/unsuspend`

| Test ID | Scenario | Expected Behavior | Expected Response / Status |
| :--- | :--- | :--- | :--- |
| **PAID-SUSP-01** | Admin suspends paid sales on an event with mixed (free and paid) tickets. | In DB, `paid_sales_activations.status` moves to `suspended`. | **HTTP 200 OK** |
| **PAID-SUSP-02** | Attendee attempts to purchase a **Paid Ticket** on this event. | Checkout transaction aborts before payment. | **HTTP 403 Forbidden**<br>`{"error": {"code": "paid_sales_suspended"}}` |
| **PAID-SUSP-03** | Attendee reserves a **Free Ticket** on the same event. | Registration **succeeds completely**. Order is created, zero-total payment processed, ticket issued. | **HTTP 201 Created** |
| **PAID-SUSP-04** | Organizer attempts to bypass paid-sales suspension via the checklist. | Organizer submission is blocked. Only platform admin can lift paid sales suspension. | **HTTP 403 Forbidden** |
| **PAID-SUSP-05** | Admin lifts paid-sales suspension (`/paid-sales/unsuspend`). | Backend re-validates that all 4 checklist steps (identity, payout, terms, fee) are intact before setting status back to `active`. | **HTTP 200 OK**<br>Paid tickets become purchasable. |

## 7. Test Cases: Operational CSV Report Export

* **UI Action:** Click "Export Events CSV" on `/admin`
* **API Endpoint:** `GET /api/v1/admin/reports/events.csv`

```bash
# Direct cURL download test:
curl -H "Authorization: Bearer <ADMIN_TOKEN>" http://localhost:8080/api/v1/admin/reports/events.csv -o operational_report.csv
```

### A. Report Verification Cases
| Test ID | Scenario | Expected Behavior | Verification Method |
| :--- | :--- | :--- | :--- |
| **CSV-01** | Authenticated Download: Click CSV Export in portal. | Next.js client fetches the file with `Authorization: Bearer` header, creates a blob URL, triggers synthetic download, and immediately revokes the object URL. | File downloads as `operational_report.csv`. |
| **CSV-02** | Header & Column Verification. | Open CSV in spreadsheet software or terminal. Confirm required columns exist:<br>`id, title, organizer_email, status, capacity, sold_count, gross_revenue_kzt, starts_at, created_at` | All expected operational columns present. |
| **CSV-03** | **RFC 4180 Escaping Check:** An event title contains quotes and commas (e.g., `Jazz, Blues & "More"`). | Backend uses Go `encoding/csv` to escape commas and double-quotes. | Title does not split across multiple spreadsheet columns. Properly escaped as: `"Jazz, Blues & ""More"""`. |
| **CSV-04** | Cache-Control Header Check. | Inspect response headers: `curl -I -H "Authorization: Bearer <TOKEN>" http://localhost:8080/api/v1/admin/reports/events.csv` | Contains `Cache-Control: no-store` so sensitive operational metrics are not cached by intermediate proxies. |

## Phase 9 Sign-Off Checklist
You can consider Platform Admin Portal & Global Moderation **PASSED** if:
- [ ] Only users with the `platform_admin` role can access `/admin`; organizers and attendees receive a clean access denied message.
- [ ] The unified search box queries users, events, orders, and payments simultaneously and debounces fast input (300 ms).
- [ ] Suspending an event immediately blocks public checkout (403 `event_suspended`) and renders a red alert banner.
- [ ] Tickets already purchased prior to an event suspension remain valid and can still be scanned at the venue gate.
- [ ] Unsuspending an event returns it to `unpublished` / `draft`, requiring the organizer to consciously republish.
- [ ] Suspending paid sales allows free registrations to continue operating uninterrupted.
- [ ] Suspending a user account immediately invalidates their active JWT sessions without waiting for token expiration.
- [ ] The operational CSV report downloads securely with bearer auth, escapes special characters properly, and serves with `Cache-Control: no-store`.
