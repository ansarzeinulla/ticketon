## 3. Test Cases: Cart Holds & Processing Fees (Checkout)

### A. 15-Minute Cart Holds (Temporary Reservations)
| Test ID | Scenario | Expected Behavior | Verification Method |
| :--- | :--- | :--- | :--- |
| **HOLD-10-01** | Select a ticket and open the checkout modal. | The database increments `quantity_reserved` (not `quantity_sold`). Inventory is held for this specific user session. | Query DB: `quantity_reserved` increases by 1. |
| **HOLD-10-02** | Abandon the checkout (Wait 15+ minutes). | The backend automatically expires the hold. The ticket is released back into the available pool. | Query DB: `quantity_reserved` decreases, `quantity_total` remains available for others. |
| **HOLD-10-03** | Concurrent Hold Limit. | Attempt to hold the last available ticket in Browser A. Attempt to hold it in Browser B. | Browser B is rejected immediately; it cannot hold a ticket currently reserved by A. |

### B. Processing Fees
| Test ID | Scenario | Expected Behavior | Verification Method |
| :--- | :--- | :--- | :--- |
| **FEE-10-01** | Execute paid checkout. | The UI displays the base price, the discount (if any), and a calculated `Processing Fee`. | The Final Total exactly matches: `Subtotal - Discount + Processing Fee`. |
| **FEE-10-02** | Verify DB storage. | After checkout, inspect the `orders` table. | `processing_fee_kzt` column correctly reflects the fee charged, and `total_kzt` includes it. |
