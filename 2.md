## 2. Test Cases: Event Creation & Image Uploads

* **UI Routes:** `/events/new`, `/dashboard/events/[id]`
* **API Endpoints:** 
  * `POST /api/v1/events`
  * `POST /api/v1/uploads/images`

### A. Normal Cases (Happy Path)
| Test ID | Input / Scenario | Expected Behavior | Expected Response / Status |
| :--- | :--- | :--- | :--- |
| **EVT-01** | Create an event filling required fields: Title, Venue Name, Venue Address, Start Date/Time, End Date/Time, Timezone (`Asia/Almaty`), Capacity. | Event is created in **`draft`** status; a unique slug is generated automatically from the title; redirects to `/dashboard/events/[id]`. | **HTTP 201 Created**<br>`status: "draft"` |
| **EVT-02** | Upload a valid banner image (`.png` or `.jpeg` < 5 MB). | The file is inspected by content (not extension), given a random name in `UPLOAD_DIR`, and a valid URL (`/uploads/{filename}`) is returned and populated in the form. | **HTTP 200 OK**<br>Returns `{ "url": "..." }` |
| **EVT-03** | Provide Cyrillic Title (e.g., `"Наурыз Мейрамы 2027"` or `"Концерт в Алматы"`). | Title is accepted; backend transliterates title to ASCII for the slug (e.g., `nauryz-meyramy-2027` or `kontsert-v-almaty`). | **HTTP 201 Created**<br>Transliterated slug. |

### B. Edge Cases
| Test ID | Input / Scenario | Expected Behavior | Expected Response / Status |
| :--- | :--- | :--- | :--- |
| **EVT-04** | Title collision: Create two events with the identical title `"Tech Meetup"`. | Backend de-duplicates slugs: First event gets `tech-meetup`, second event automatically gets `tech-meetup-2`. | **HTTP 201 Created** for both. |
| **EVT-05** | Timezone Handling across DST/Off-zones: Set start time to `19:00` with timezone `Asia/Almaty` while your testing browser/machine is set to another timezone. | Frontend `localInputToISO()` converts with correct IANA zone offset (`+05:00` or configured offset); dashboard renders back exactly `19:00`, not converted to browser local time. | RFC 3339 string preserved with correct offset. |
| **EVT-06** | Boundary date limits: Set `ends_at` to exactly 1 second after `starts_at`. | Accepted by validation logic. | **HTTP 201 Created** |

### C. Error Cases & What Errors Must Appear
| Test ID | Input / Scenario | Expected Error Code / Message | HTTP Status |
| :--- | :--- | :--- | :--- |
| **EVT-ERR-01** | End time before or equal to start time (`ends_at <= starts_at`). | **JSON:** `{"error": {"code": "validation_failed", "fields": {"ends_at": "End time must be after the start time."}}}`<br>**UI:** Field-level red error on the "End Time" input. | **422 Unprocessable Entity** |
| **EVT-ERR-02** | Missing required fields (e.g., empty title or empty start time). | **JSON:** `{"error": {"code": "validation_failed", "fields": {"title": "Title is required."}}}` | **422 Unprocessable Entity** |
| **EVT-ERR-03** | Image upload exceeding 5 MB limit. | Form rejects before or during upload stream. **JSON:** `{"error": {"code": "file_too_large", "message": "File exceeds 5MB limit."}}` | **400 Bad Request** or **413 Payload Too Large** |
| **EVT-ERR-04** | Upload non-image disguised file (e.g., `.txt` or `.exe` renamed to `banner.png`). | Backend `http.DetectContentType` inspects first 512 bytes, rejects non-image MIME type. | **400 Bad Request** (`invalid_file_type`) |

## 3. Test Cases: Event Lifecycle & Modifications

* **UI Route:** `/dashboard/events/[id]`
* **API Endpoints:**
  * `PATCH /api/v1/events/{id}`
  * `POST /api/v1/events/{id}/publish`
  * `POST /api/v1/events/{id}/unpublish`
  * `POST /api/v1/events/{id}/cancel`
  * `DELETE /api/v1/events/{id}`

### State Machine Rules
```
         ┌───────────────┐
         │     DRAFT     │◄──────────────┐
         └───────┬───────┘               │
                 │ publish               │ unpublish
                 ▼                       │
         ┌───────────────┐               │
         │   PUBLISHED   ├───────────────┘
         └───────┬───────┘
                 │ cancel
                 ▼
         ┌───────────────┐
         │   CANCELLED   │ (terminal state)
         └───────────────┘
```

### A. Normal Cases (Happy Path)
| Test ID | Input / Scenario | Expected Behavior | Expected Response / Status |
| :--- | :--- | :--- | :--- |
| **LIFE-01** | Publish Draft: Click "Publish" on a draft event. | Status moves to `published`. Event now becomes visible in public search queries and public slug view. Audit log records `event.published`. | **HTTP 200 OK** |
| **LIFE-02** | Unpublish Event: Click "Unpublish" on a published event with zero sales. | Status returns to `unpublished` (or `draft`). Event is removed from public catalogue. | **HTTP 200 OK** |
| **LIFE-03** | Cancel Event: Click "Cancel" on a published event. | Status changes to `cancelled`. Public page renders cancelled banner; purchasing is blocked permanently. Console terminal prints mock `event.cancelled` emails for ticket holders. | **HTTP 200 OK** |
| **LIFE-04** | Delete Draft: Click "Delete" on an unpublished draft event. | Event row is deleted from database completely. Redirects to `/dashboard`. | **HTTP 200 OK** or **204 No Content** |
| **LIFE-05** | Partial Update (PATCH): Submit update with only `description` changed. | Only `description` is modified. Omitted fields remain completely untouched. | **HTTP 200 OK** |
| **LIFE-06** | Nullifying an optional field: Send PATCH with `"description": null`. | Optional column is reset to NULL/empty without breaking required fields. | **HTTP 200 OK** |

### B. Edge Cases & Guardrails
| Test ID | Input / Scenario | Expected Behavior | Expected Response / Status |
| :--- | :--- | :--- | :--- |
| **LIFE-07** | Organizer Isolation: Log in as Organizer B (`timur@biletflow.kz`) and attempt to edit Organizer A's (`dana@biletflow.kz`) event ID via direct API call. | Request is rejected; organizer can never view or mutate another user's event. | **HTTP 403 Forbidden** or **404 Not Found** |
| **LIFE-08** | Audit Trail Permanence: Query `audit_logs` table in PostgreSQL after editing and publishing an event. | Every lifecycle transition has an immutable row containing `actor_id`, `event_id`, action type, and timestamp. | Rows exist in DB. |

### C. Error Cases & What Errors Must Appear
| Test ID | Input / Scenario | Expected Error Code / Message | HTTP Status |
| :--- | :--- | :--- | :--- |
| **LIFE-ERR-01** | Delete a Published or Active Event: Attempt to DELETE an event that is currently `published`. | **JSON:** `{"error": {"code": "conflict", "message": "Only draft events can be deleted. Cancel the event instead."}}` | **409 Conflict** |
| **LIFE-ERR-02** | Re-publish a Cancelled Event: Call `/publish` on an event with status `cancelled`. | State machine violation: Terminal state cannot be transitioned. **JSON:** `{"error": {"code": "conflict", "message": "Cancelled events cannot be republished."}}` | **409 Conflict** |
| **LIFE-ERR-03** | Publish with invalid dates: Set `ends_at` in the past and attempt to publish. | Validation blocks publishing an expired event. | **422 Unprocessable Entity** |

Hide it instead."}}` | **409 Conflict** |
| **TKT-ERR-04** | Sales Window Inversion: Set `sales_end_at` before `sales_start_at`. | **JSON:** `{"error": {"code": "validation_failed", "fields": {"sales_end_at": "Sales end must be after sales start."}}}` | **422 Unprocessable Entity** |

## 6. Test Cases: Dashboard Lifecycle Tabs

* **UI Route:** `/dashboard`
* **API Endpoint:** `GET /api/v1/events/mine?lifecycle=...`

The dashboard derives the lifecycle bucket dynamically on the fly:
* **`draft`:** `status == 'draft'`
* **`upcoming`:** `status == 'published'` AND `starts_at > now()`
* **`active`:** `status == 'published'` AND `starts_at <= now() <= ends_at`
* **`completed`:** `status == 'published'` AND `ends_at < now()`
* **`cancelled`:** `status == 'cancelled'`
* **`suspended`:** `status == 'suspended'`

### A. Lifecycle Bucket Verification
| Test ID | Scenario | Expected Tab Location |
| :--- | :--- | :--- |
| **DSH-01** | Freshly created event (unpublished). | Appears in **Drafts** tab; hidden from public catalogue. |
| **DSH-02** | Published event with date in 2027. | Appears in **Upcoming** tab. |
| **DSH-03** | Event whose start time was 10 mins ago and end time is 2 hours ahead. | Appears in **Active** tab. |
| **DSH-04** | Event whose `ends_at` was yesterday. | Automatically moves to **Completed** tab without database cron jobs. |
| **DSH-05** | Cancelled event. | Appears in **Cancelled** tab with grey/red badge. |

## Phase 2 Sign-Off Checklist
You can consider Organizer Event & Ticket Management **PASSED** if:
- [ ] Events start as drafts and generate de-duplicated, transliterated slugs.
- [ ] Images over 5 MB or non-image files are rejected.
- [ ] Dates and times strictly honor the event's configured IANA timezone (`Asia/Almaty`).
- [ ] An event cannot be published if the end time is before the start time.
- [ ] Deleting an event with sales or an active published status returns HTTP 409.
- [ ] Ticket prices and inventory operate with exact decimal strings (`numeric(14,2)`), never floating-point rounding.
- [ ] Ticket types with existing sales cannot be deleted (only hidden).
- [ ] Duplicating an event copies settings and ticket types with 0 sold, completely excluding past attendees, orders, promos, and support cases.
- [ ] Organizers cannot view or edit events owned by another account.
